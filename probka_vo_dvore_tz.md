Версия: 0.1

## 0. Утвержденные продуктовые решения

По состоянию на 27.05.2026 утверждено:

- название: "Пробка во дворе";
- тон: городской;
- сложность: умеренная, с заметным ростом по мере прохождения;
- монетизация: максимально активная рекламная модель в рамках правил платформы;
- графика: приятная 2D-картинка, без дорогого производства ассетов, но с аккуратным визуалом и стабильной работой.

Практический перевод этих решений:

- игра должна ощущаться как городская парковочная головоломка, а не как стерильная абстрактная парковка;
- первые уровни простые, но после обучения игра постепенно вынуждает думать;
- реклама используется везде, где это не ломает правила Yandex Games и не мешает активному gameplay;
- визуальный стиль строится на чистых top-down машинах, асфальте, разметке, дворовых объектах и сочных feedback-анимациях.

## 1. Короткое описание

"Пробка во дворе" - залипательная 2D-головоломка про выезд из забитого двора. Игрок двигает машины по клеточному полю, освобождает путь для целевой машины и проходит короткие уровни за 30-120 секунд.

Продуктовая формула:

> Rush Hour / parking jam + московский двор + короткие уровни + реклама за подсказки и пропуски.

Первая цель - выпустить игру на Yandex Games, проверить удержание, рекламную монетизацию и интерес к уровневым пакам.

## 5. Core gameplay

### 5.1 Основная механика

Игровое поле - прямоугольная сетка. На поле стоят машины и препятствия.

Правила:

- каждая машина занимает 2-3 клетки;
- машина может двигаться только вдоль своей оси:
  - горизонтальная - влево/вправо;
  - вертикальная - вверх/вниз;
- машина не может проходить сквозь другие машины или препятствия;
- цель - вывести главную машину через выход;
- игрок двигает машины свайпом/drag gesture;
- уровень завершается, когда главная машина покидает поле.

### 5.2 Отличие от обычного parking puzzle

Локальные элементы:

- двор с хаотичной парковкой;
- шлагбаум;
- сугроб;
- мусорные баки;
- такси;
- доставка;
- каршеринг;
- узкий выезд;
- "место занято конусом";
- дворник как препятствие/таймерный объект в поздних уровнях.

В MVP часть этих элементов может быть декоративной. Механически обязательны только машины, препятствия и выход.

### 5.3 Core loop

1. Игрок открывает уровень.
2. Видит цель: вывести красную/главную машину.
3. Двигает машины.
4. Проходит уровень.
5. Получает звезды/монеты.
6. Открывает следующий уровень.
7. При затруднении берет подсказку, пропуск или перезапуск.

## 6. Уровни

### 6.1 Объем первого релиза

MVP:

- 60 уровней;
- 5 обучающих;
- 35 easy/medium;
- 20 более сложных.

Кривая сложности:

- уровни 1-5: обучение без давления;
- уровни 6-20: легкие городские пробки;
- уровни 21-40: умеренные уровни с 1-2 ключевыми перестановками;
- уровни 41-60: заметно сложнее, часть игроков должна использовать подсказки;
- после 60 уровня: паки с растущей сложностью и большим числом блокировок.

Версия 1.0:

- 100-120 уровней;
- 5-6 тематических паков;
- постепенное добавление новых элементов.

### 6.2 Паки уровней

Паки для версии 1.0:

1. "Первый двор"
   - простые уровни;
   - обучение движению;
   - размер поля 6x6.

2. "После работы"
   - больше машин;
   - меньше свободного места.

3. "Снег выпал"
   - сугробы как неподвижные блоки;
   - узкие коридоры.

4. "Шлагбаум"
   - выход заблокирован объектом, который открывается после перемещения ключевой машины.

5. "Каршеринг встал"
   - длинные машины, автобусы/газели 3 клетки.

6. "Двор без надежды"
   - сложные puzzle-уровни для удержания.

### 6.3 Рейтинг уровня

Звезды:

- 3 звезды: прошел за targetMoves или меньше;
- 2 звезды: прошел за targetMoves + запас;
- 1 звезда: прошел любым количеством ходов.

Звезды нужны для:

- ощущения мастерства;
- открытия будущих паков;
- мотивации перепроходить уровни;
- метрики сложности.

В MVP не блокируем основной прогресс звездами, чтобы не душить casual-аудиторию.

## 7. Структура данных уровней

Уровни хранятся статически в JSON внутри игры:

```json

  "packId": "first_yard",
  "title": "Первый выезд",
  "grid": {
    "width": 6,
    "height": 6
  },
  "exit": {
    "side": "right",
    "row": 2
  },
  "targetVehicleId": "car_red",
  "targetMoves": {
    "threeStars": 8,
    "twoStars": 14
  },
  "vehicles": [
    {
      "id": "car_red",
      "kind": "car",
      "x": 1,
      "y": 2,
      "length": 2,
      "axis": "horizontal",
      "skin": "red"
    },
    {
      "id": "car_blue",
      "kind": "car",
      "x": 3,
      "y": 0,
      "length": 3,
      "axis": "vertical",
      "skin": "blue"
    }
  ],
  "obstacles": [
    {
      "id": "bin_1",
      "kind": "trash_bin",
      "x": 5,
      "y": 4
    }
  ],
  "solution": [
    { "vehicleId": "car_blue", "delta": 1 },
    { "vehicleId": "car_red", "delta": 4 }
  ]
}
```

### 7.1 Почему JSON

- быстро создавать и править уровни;
- можно генерировать уровни с моей помощью;
- удобно валидировать;
- не нужен встроенный редактор на первом этапе;
- легко добавить level packs.

### 7.2 Валидатор уровней

Нужен dev-инструмент:

- проверка, что машины не пересекаются;
- проверка, что объекты не выходят за поле;
- проверка, что есть targetVehicle;
- проверка, что exit совпадает с осью targetVehicle;
- проверка, что уровень потенциально решаем, если есть solution;
- подсчет минимальности решения можно отложить.

## 9. Управление

Mobile:

## 11. Монетизация

### 11.1 Главная модель

Основная модель первого релиза:

- rewarded ads;
- interstitial ads между уровнями;
- sticky banner только там, где он не мешает gameplay;
- in-app purchases как второй этап.

Утвержденный режим: рекламная монетизация максимальная, но compliant. Это значит, что игра использует все доступные рекламные форматы, однако не провоцирует случайные клики и не показывает fullscreen-рекламу внутри активного движения машины.

### 11.2 Реклама

Форматы:

1. Rewarded video
   - добровольный просмотр;
   - награды:
     - +1 подсказка;
     - x2 монеты;
     - пропуск уровня;
     - открыть скин на 24 часа.

2. Interstitial
   - показывать на логических переходах:
     - после 3-5 уровней;
     - после проигрыша/перезапуска не чаще заданного лимита;
     - между паками;
   - стартовый режим для максимальной монетизации: не показывать до прохождения первых 3 уровней, затем показывать максимально часто на разрешенных переходах;
   - не показывать во время активного движения/уровня.

3. Sticky banner
   - включить в меню, выборе уровней, магазине и win screen;
   - в gameplay показывать только если остается безопасная зона и баннер не закрывает поле/кнопки;
   - если на маленьких экранах баннер портит gameplay, отключать его во время уровня.

Технические требования:

- реклама вызывается только через Yandex Games SDK;
- во время fullscreen ads игра и звук ставятся на паузу;
- игрок должен ясно понимать, какую награду получит за rewarded ad;
- случайные клики по рекламе нельзя провоцировать интерфейсом.

### 11.3 In-app purchases

Покупки подключаются после базового релиза и проверки retention.

Кандидаты:

```text
no_ads              - убрать interstitial/sticky ads
hints_10            - 10 подсказок
hints_30            - 30 подсказок
premium_cars_pack   - набор скинов машин
yard_themes_pack    - визуальные темы двора
unlock_all_levels   - открыть все уровни
```

Важно:

- в Yandex Games покупки используют портальную валюту;
- цены задаются в консоли;
- для покупок нужно подключение монетизации/YAN и обработка неучтенных платежей;
- в коде должен быть слой PurchaseService, даже если сами покупки включим позже.

### 11.4 Баланс рекламы

Стартовый баланс:

- первые 3 уровня без interstitial;
- далее interstitial на каждом допустимом переходе, если Yandex Games SDK/platform frequency cap позволяет;
- rewarded ads доступны всегда, но только по инициативе игрока;
- если игрок купил no_ads, interstitial и sticky banner отключаются, rewarded остается добровольным.

Дополнительные рекламные точки:

- x2 монеты на win screen;
- +1 подсказка из game screen;
- пропуск уровня из stuck state;
- продолжить streak daily reward x2;
- открыть временный городской скин;
- открыть следующий сложный уровень без накопления звезд, если такая блокировка появится.

### 11.5 Метрики монетизации

Смотреть:

- DAU;
- D1 retention;
- D7 retention;
- средняя сессия;
- уровней за сессию;
- interstitial impressions per DAU;
- rewarded opt-in rate;
- completion rate уровней;
- где игроки застревают;
- ARPDAU;
- доход на 1000 игроков.

## 12. Хранение данных

### 12.1 Что хранить в игре

Статические данные:

- паки;
- скины;
- цены/ID покупок;
- базовые настройки.

Эти данные хранятся в исходниках игры и попадают в build.

Пользовательские данные:

- текущий уровень;
- открытые уровни;
- звезды по уровням;
- bestMoves по уровням;
- монеты;
- количество подсказок;
- купленные предметы;
- выбранный скин;
- настройки звука;
- дата daily reward;
- счетчики рекламы и лимиты.

### 12.2 Где хранить прогресс

MVP storage strategy:

1. Локально:
   - localStorage;
   - на Yandex Games использовать safeStorage, если доступен через SDK.

2. Облачно:
   - Yandex Games Player Data через `player.setData()` и `player.getData()`;
   - сохранять компактный объект прогресса.

3. Статистика:
   - числовые значения можно хранить через `player.setStats()`;
   - например totalWins, totalMoves, currentLevel, starsTotal.

4. Собственный backend:
   - не нужен в MVP;
   - нужен позже, если появятся турниры, антифрод, сложные аккаунты или кросс-платформенное хранение вне Yandex.

Официальные ограничения Yandex Games:

- `player.setData()` - до 200 KB на игрока;
- `player.setStats()` - до 10 KB числовых данных;
- частые запросы имеют rate limits, поэтому сохранять надо не на каждый пиксель движения, а на значимые события.

### 12.3 Формат сохранения

### 12.4 Save triggers

Сохранять:

- после прохождения уровня;
- после покупки/получения награды;
- после изменения настроек;
- после daily reward;
- после выбора скина;
- при уходе приложения в background, если доступно.

Не сохранять:

- после каждого drag;
- после каждого кадра;
- слишком часто во время одного уровня.

## 15. Визуальный стиль

Стиль:

- top-down 2D;
- яркие машины без реальных брендов;
- двор как плитка/асфальт;
- понятные препятствия;
- минимум визуального шума;
- читаемость важнее реализма.

Цвета:

- целевая машина - красная или желтая;
- обычные машины - синие, зеленые, белые, серые;
- препятствия - контрастные;
- выход - визуально подсвечен.

Темы:

- летний двор;
- зимний двор;
- вечер;
- торговый центр;
- бизнес-центр.

Для MVP:

- один основной двор;
- простые машины;
- 1-2 декоративных препятствия.

## 16. Звук и ощущения

Нужны:

- звук drag/move;
- звук упора в препятствие;
- звук победы;
- звук монет;
- мягкий haptic-like feedback через визуальные эффекты;
- короткие particle effects на победе.

Музыка:

- optional;
- лучше тихий loop в меню;
- в gameplay можно оставить только sfx.

Во время рекламы:

- поставить игру на паузу;
- выключить/приглушить звук;
- после рекламы восстановить состояние.

## 17. UX и удержание

Первые 60 секунд:

- сразу дать играть;
- не показывать рекламу;
- не просить регистрацию;
- не перегружать меню;
- обучение через действия, а не длинный текст.

Retention-механики:

- daily reward;
- новые паки;
- звезды;
- скины машин;
- "сложный уровень дня" в будущей версии;
- streak за ежедневный вход.

Что нельзя:

- длинные туториалы;
- резкий difficulty spike до 10 уровня;
- реклама в первые минуты;
- сложные правила в начале;
- маленькие кликабельные элементы.

## 20. Правила и ограничения платформы

Для Yandex Games учитываем:

- реклама вызывается только через SDK;
- fullscreen ads должны ставить игру и звук на паузу;
- rewarded ads должны быть добровольными и с понятной наградой;
- interstitial показываются на логических паузах;
- документы/правила не открываются внешней ссылкой, а добавляются текстом внутри игры;
- не использовать внешние переходы, если это запрещено требованиями;
- не вводить игрока в заблуждение рекламой или UI.

- победа и переход на следующий уровень;
- stars по ходам;
- сохранение прогресса;
- монеты;
- подсказка;
- rewarded ad stub/dev fallback;
- interstitial ad integration or stub;
- Yandex SDK wrapper;
- адаптация под мобильный экран;
- базовые звуки;
- валидатор уровней;

Не входит в MVP:

- десятки тем;
- Android wrapper;

- полноценная покупка no_ads, если монетизация еще не подключена в консоли.

## 23. План разработки

Оценка: 18-25 сессий по 5 часов для первой нормальной версии.

### Этап 1: прототип, 2-3 сессии

Готово, когда:

- есть Phaser/Vite проект;
- есть поле 6x6;
- машины двигаются;
- есть столкновения;
- уровень можно выиграть.

### Этап 2: игровой каркас, 3-4 сессии

Готово, когда:

- уровни грузятся из JSON;
- есть GameScene;
- есть win condition;
- есть переход между уровнями;
- есть restart/undo/hint stub.

### Этап 3: прогресс и экономика, 3-4 сессии

Готово, когда:

- сохраняется прогресс;
- считаются звезды;
- выдаются монеты;
- есть level select;
- есть базовый shop.

### Этап 4: контент, 4-6 сессий

Готово, когда:

- есть 60 уровней;
- уровни валидируются;
- сложность растет плавно;
- tutorial понятен без текста или с минимумом текста.

### Этап 5: Yandex SDK и монетизация, 2-3 сессии

Готово, когда:

- SDK инициализируется;
- сохранение работает через Yandex, где возможно;
- rewarded/interstitial интегрированы или подготовлены;
- игра корректно ставится на паузу во время рекламы.

### Этап 6: полировка и публикация, 4-5 сессий

Готово, когда:

- UI адаптирован под телефоны;
- нет критичных багов;
- есть звук/эффекты;
- есть иконка/обложка/скриншоты;
- production build проходит локальную проверку;
- игра готова к загрузке в консоль.

## 24. Риски

1. Игра слишком похожа на обычный parking jam.
   - Решение: локальный визуальный крючок, название, мемные элементы, аккуратная упаковка.

2. Уровни скучные или слишком простые.
   - Решение: тестировать после первых 15-20 уровней, менять кривую сложности.

3. Реклама раздражает.
   - Решение: первые минуты без рекламы, rewarded как основной формат, interstitial только на паузах.

4. Монетизация Yandex покупок подключается не сразу.
   - Решение: первый релиз строить на рекламе, покупки держать как интерфейсный/кодовый запас.

5. Нет трафика.
   - Решение: нормальная обложка, название, скриншоты, короткие ролики, публикация в чатах, тест названия.

6. Сложно быстро сделать красивую графику.
   - Решение: начать с чистого top-down стиля, где аккуратность важнее детализации.

## 25. Критерии успеха первого релиза

Минимальные:

- игра опубликована;
- пользователь может пройти 30+ уровней без критичных багов;
- D1 retention больше 15%;
- rewarded ads смотрят хотя бы 10-20% игроков;
- средняя сессия больше 4 минут.

Хорошие:

- D1 retention 25%+;
- игрок проходит 8+ уровней за первую сессию;
- rewarded opt-in 25%+;
- есть органические возвраты на следующий день;
- игроки доходят до 30+ уровня.

Отличные:

- Yandex Games дает органический трафик;
- D7 retention 8-10%+;
- появляются комментарии/оценки;
- есть смысл делать 200 уровней и Android-версию.

## 27. Источники и проверенные платформенные факты

- Yandex Games поддерживает монетизацию через рекламу и in-app purchases.
- Реклама в Yandex Games вызывается через SDK; rewarded ads добровольные, interstitial показываются на логических паузах.
- Yandex Games Player Data позволяет сохранять данные игрока на сервере Yandex; `player.setData()` имеет лимит 200 KB, `player.setStats()` - 10 KB.
- Для in-app purchases нужно подключение покупок в консоли и обработка неучтенных платежей.
